# SmartUI UI 制作与 Unity 交付改进计划

## 任务汇总

| Task | 优先级 | 交付 | 状态 |
| --- | --- | --- | --- |
| 1 | P0 | 整合现有规范与开工检查 | 项目设置与制作流程已实现，Unity 滚动行为待工程验收 |
| 2 | P0 | 补充现有页面构建的 Unity 适配交付与标注 | 已实现标注与 RectTransform 映射，滚动接入及 Unity 工程验收待验证 |
| 3 | P0 | 检查设计稿和 Unity 交付，并同步 Unity 中采纳的修改 | 待实施 |
| 4 | P1 | 公共控件与图素复用查询 | 待实施 |

## Task 1 · 整合现有规范与开工检查

- **文档**：在[项目工具文档](project-tools.md)中集中说明通用规则和项目设置各自从哪里读取。通用的对齐、间距与适配检查归入现有布局检查说明。项目的视觉规则、字体角色和控件用法分别沿用现有风格规则、文字规范和组件使用约定，每条规则只在其归属处维护。
- **协议与工具**：从项目上下文读取已有规则和工程约定，仅补参考分辨率、滚动默认行为等尚缺且工具需要使用的项目设置。图集、本地化与资源加载规则优先引用现有工程约定。滚动设置包含 `Elastic` 或 `Clamped`，并明确少量内容能否拖动。
- **Skill**：开工时通过项目上下文核对本次任务相关的规则，只补会影响设计或交付的缺项。
- **验收**：已有规范齐全的项目可直接开始制作。纯静态页面的检查无需填写滚动设置。普通列表继承默认值，特殊列表能追溯覆盖值和原因。

## Task 2 · 补充现有页面构建的 Unity 适配交付与标注

- **文档与协议**：更新[项目工具文档](project-tools.md)和 [Unity 接入设计](unity-integration-plan.md)。沿用 `project_save_layout` 已有的节点 ID、分组、排列、对齐、安全区与资产几何。仅为现有布局无法表达的 Unity 适配意图补充字段，例如关键节点的锚定、拉伸和枢轴，以及列表遮罩与内容边距。
- **工具与 Skill**：在 `project_build_layout` 的现有 HTML 与 PNG 构建上复用检查叠加层，按需导出标注图。沿用 `project_preview_layout_variants` 检查不同尺寸和安全区。更新页面组合 Skill，让 Unity 接入读取同一布局版本的结构化约束和标注图。Unity 属性映射随交付记录，实测值进入复验结果。
- **验收**：干净稿、标注图和结构化交付数据来自同一布局版本。按标注在 Unity 落地后，使用参考分辨率和不同宽高比核对适配。以图文组、独立角标和空／少／满列表核对整体居中、独立锚定、遮罩和末行留白。

## Task 3 · 检查设计稿和 Unity 交付，并同步 Unity 中采纳的修改

- **文档与 Skill**：新增设计稿和 Unity 交付清单模板，更新 [Unity 接入工具文档](unity-tools.md) 及相关 Skill 的完成流程。每项记录通过、失败、待验证或不适用，并关联检查证据。
- **第一步 · 只读复验**：扩展 Unity `plan / apply / verify` 的预检、复验和回执，按本次变更界面检查参考分辨率或已登记的例外。核对 Unity 实际适配、公共引用和对齐偏差，输出同场景设计与 Unity 对照。由项目适配器比对本地化 Key、权威源表和生成结果，报告缺项、值不一致及按项目规则识别的占位。
- **第二步 · 将采纳的 Unity 修改同步到 SmartUI**：在 Unity 调优后和 SmartUI 再次下发前，对照上次同步基线、当前设计和当前 Unity。首批支持稳定 ID 下能明确映射到设计约束的属性，以及来源明确的资产更新。按页面实例、变体、公共 Prefab 或共享图素的归属生成采纳方案，采纳后更新对应定义、预览和基线，并列出受影响页面。同一属性双方均有改动时报告三方值。结构变更与无法确定设计意图的差异列为待处理项。
- **验收**：检查本次修改界面是否按项目参考分辨率制作，并在目标尺寸场景核对实际适配。分别记录几何与引用、点击与滚动、业务结果。用页面、公共 Prefab 和共享图素验证人工修改、差异检测、选择性采纳及重新生成的完整往返。已采纳的调优应保留，重复同步无新增差异。

## Task 4 · 公共控件与图素复用查询

- **文档与协议**：更新 [项目工具文档](project-tools.md)，沿用现有公共 Prefab 目录、资产登记和导出清单。按查询缺口补公共标记和必要字段。
- **工具与 Skill**：提供面向 Agent 的结构化查询，返回已有 ID、用途、预览、来源、尺寸和切片约束、使用位置与同步状态。更新制作 Skill，开工先查公共控件和图素，再按需查看候选预览。
- **验收**：Agent 能按用途查到候选，识别过期或待同步原因，并在新页面直接复用已有 ID。

各项完成后更新 [工具链总体规划](toolchain-roadmap.md) 的状态和实际验证结果。仓库保存通用协议、模板、实现与验证方法，项目规范、素材和验收产物保存在业务项目内。
