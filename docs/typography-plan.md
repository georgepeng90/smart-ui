# 项目文字设计规范与页面应用

## 1. 文字规范的用途

项目根据参考、内容层级和目标显示尺寸建立文字规范。正式页面按内容角色引用基准字号和完整角色样式，使字体、字号、填色、描边和投影跨页一致。规范更新后，可以查询角色的使用位置，并识别需要重新构建和复查的页面。

正式页面和文字样片使用同一条 Chromium 渲染路径。使用 Pillow 的简单静态组合提供独立的预览功能，正式文字规范的技术检查和视觉校准使用 Chromium 页面。

## 2. 从参考形成规范

### 2.1 分析内容角色及视觉特征

先查看完整参考中的信息层级，再选择有代表性的文字区域。角色按内容用途划分，以下类别仅用于说明，具体项目可以合并或调整，不要求凑齐固定数量。

用途还应说明文字主要用于持续阅读、快速扫读还是短时演出。Cygames 的设计师访谈将对白、帮助等信息文字与活动标志、胜利字样分别处理。展示文字可以承担更强的风格表达，正文、帮助和关键操作信息需单独校准可读性。 [Cygames 设计师访谈](https://magazine.cygames.co.jp/ja/archives/1579151063)

| 内容角色 | 需要判断的关系 |
| --- | --- |
| 页面标题 | 页面身份、主要视觉重心及与正文的大小关系 |
| 模块标题 | 同级模块是否一致、与页面标题的层级关系 |
| 操作文字 | 按钮用途、重要程度、状态和容器留白 |
| 正文 | 连续阅读、信息密度、行距与换行 |
| 辅助说明 | 次要信息的可读性及与正文的区别 |
| 关键数值 | 数量、价格或结果的强调程度、数字字形与单位关系 |

每个代表区域分析以下适用维度：

| 维度 | 记录内容 |
| --- | --- |
| 字体与字形 | 字体特征、字重、倾斜、中英文及数字的差异、项目可用字体 |
| 字号与排版 | 可见字形大小、相对层级、行高、字距、对齐、行数和留白 |
| 填色 | 颜色、透明度、内容用途、状态区别及背景对比 |
| 描边 | 颜色、透明度、粗细、字形内外的视觉效果 |
| 投影 | 颜色、透明度、偏移方向与距离、模糊程度 |
| 适用条件 | 背景、容器、显示尺寸，以及哪些角色或状态使用该样式 |

分析保留参考 ID、区域及测量所用坐标尺寸，区分可见观察、制作假设和准备采用的参数。截图中的可见字形高度和字体字号需要分别记录。经过缩放、抗锯齿和背景混色的颜色也不能直接当作原始设计参数。不能从截图唯一确定的字体、字号或效果参数，需要用实际字体样片校准。没有出现的状态按项目需求补充，明确设计理由与待验证项。

### 2.2 固定字号档位与完整角色样式

项目记录设计基准尺寸，字号、行高、字距、描边和投影以该基准下的像素为单位。参考截图先换算到可比显示尺度，再判断相对关系。浏览器查看缩放不修改设计值；改变设计基准时需明确调整规范和布局，不通过单独改变画布尺寸推导新的字号。

先归纳少量固定字号档位，再为内容角色选择档位。档位数量和数值由参考与实际样片决定，工具不内置统一字号表，不强制等比级数，也不为每种角色分配独占字号。不同角色可以共用字号，通过字体、颜色和效果区分用途。

每个角色样式包含完整外观及用途。例如 `page-title`、`section-title`、`body`、`button-primary`、`value-important`。标识表达内容用途，不使用具体字号命名。需要状态差异时定义明确的完整样式，例如 `button-primary-disabled`；角色样式独立定义，页面节点只引用完整样式。需要保持一致的状态关系写入使用规则，并通过样片复查。

字号档位只保存字号数值；行高属于角色样式。同一字号用于单行按钮和多行说明时，可以采用不同的行高。对齐、换行和文本框属于具体页面布局。

固定档位为同一套适用条件下的页面提供基准字号。规范说明目标设备、显示尺度、语言范围和阅读场景，每套规范先校准明确的一组条件。需要支持其他语言或玩家选择的大字模式时，应按相应条件校准。页面默认从角色字号排版，只有节点明确选择 `shrink` 才会在指定范围内缩字。相关设计经验见第 7 节。

### 2.3 样片校准与页面验证

使用与正式页面相同的字体、样式解析和 Chromium 渲染路径制作样片，覆盖本次实际需要的角色和状态。样片包含真实中文、数字、单位、短操作文字及多行说明，并置于适用的背景或组件中；不为校准提前制作完整页面。

样片同时包含最长的实际标签、多行正文和容易混淆的字形。中文检查复杂汉字的笔画空隙；项目包含日语时检查汉字、假名和实际断行，包含法语时使用真实译文、重音字符和项目采用的标点。多语言样片属于针对项目输入的人工设计检查，多语言样式切换和完整排版规则校验需另行实现。

除了设计画布，还应在目标设备的实际显示大小和典型观看距离下检查。动态场景中的 HUD（游戏画面上的常驻信息）按需使用亮、暗、复杂背景的代表帧复查；持续运动中的辨识留到运行态验收。静态浏览器截图不能替代手机实机、玩家反馈或运行态验证。社区实践强调用最不利的文本区域和显示条件确定字号，并在运动背景中核对 HUD。[John Burnett 的游戏 UI 经验](https://www.reddit.com/r/gamedev/comments/ifsnpf/)

先按目标显示尺寸检查层级、可读性、字形重量、描边、投影及留白，再用放大检查定位问题。汇总共同偏差后修改角色样式，复查受影响样片。实际页面再验证内容角色选择和整页层级。没有新偏差时复用已有结果，不增加固定轮数或逐步骤人工审批。

技术检查、模型视觉判断和用户风格确认分别记录。样片校准完成不能直接宣称所有页面或其他渲染平台都已验收。

## 3. 文字规范、页面和构建记录

文字规范是项目中的独立数据域。项目索引在 `smart-ui/project.json` 使用 schema 5，在定义规范后引用 `smart-ui/typography.json`，同时保存文件摘要并在读取时校验。工具生成 `smart-ui/docs/typography.md`，展示字号档位、角色用途、实际参数和参考依据。文字规范与组件绘制使用的 `style.parameters` 分开维护，文字调整不改变基础组件的风格摘要。

| 对象 | 保存内容 |
| --- | --- |
| 文字规范 | 设计基准尺寸、说明、字号档位和角色样式 |
| 字号档位 | 稳定 ID 和正整数字号 |
| 角色样式 | 稳定 ID、名称、用途、字号档位、字体路径和摘要、行高、字距、填色、描边、投影及参考依据 |
| 页面文字节点 | 节点 ID、`text_style_id`、文案、文本框、对齐、换行、溢出策略及可选行数限制 |
| 构建快照 | 引用的角色 ID、解析值、依赖摘要、包含字体的离线 HTML 和 PNG |

字号和行高使用正整数像素。字距和投影偏移允许有限的有符号像素值，描边宽度和投影模糊值为有限的非负像素值。填色、描边和投影分别保存自己的 `color` 和 `opacity`。颜色为 `#RRGGBB`，透明度范围为 0 至 1。`stroke` 和 `shadow` 可以显式设为 `null`，透明度为零的效果不占用预留空间。

角色直接引用工程内持久的 TTF 或 OTF 文件，以相对路径和内容摘要保存。用字体文件选择实际字重和字形，Chromium 禁用浏览器合成粗体或斜体。工具会报告字体缺失、文件摘要不符或缺字。请核对字体并修正规范。

## 4. 从样片到页面的工作流程

### 4.1 保存规范与引用角色

使用 `reference-style` Skill 分析参考、划分角色并校准样片。用 `project_update_typography` 和当前 `expected_revision` 保存完整文字规范。工具校验参数、参考、字体和引用，并生成受管文档。被角色引用的字号档位或被页面、Unity 控件使用的角色须先解除引用才能删除，报错会指出引用位置。Unity 控件的角色引用通过 `project_define_unity_control` 调整。

使用 `page-composition` Skill，通过 `project_context` 读取规范，为正式页面的文字节点指定 `text_style_id`。保存和构建使用相同的样式解析与字体校验。角色是否符合文案用途和页面层级由设计者判断，并以实际页面复查。

文案放不下时检查角色选择、容器、换行和内容约束。确实需要新角色或字号时修改项目规范，写明适用范围。行、列和叠放分组内的不换行单行文字可采用 `width: "content"`，由 Chromium 测量内容和效果需要的宽度，再安排同组节点。需要对齐不同字体或字号的单行文字时，可用行分组的 `align: "baseline"`。

### 4.2 文字效果与边界

Chromium 正式页面支持纯色填充、字距、单层描边和单层字形投影。描边宽度是描边的总宽度，计算外侧预留时取一半。

效果按角色和背景选择。先检查字体字形、字号、填色与底板的对比，再比较无效果、描边或投影的样片。小号中文需检查笔画是否粘连，短时展示文字可以按参考采用更强的效果。中文聊天窗口分析和日本独立开发者的实机尝试得到不同选择，是否使用描边应结合实际背景、字形和显示尺寸判断。 [聊天文字案例分析](https://www.gameres.com/689352.html)、[日语卡牌游戏制作记录](https://note.com/sait3110c/n/nc40ba04bae50)

每侧的 `effect_insets` 取描边外伸与该侧投影预算的较大值。模糊值大于零时，投影从 `ceil(2 * blur) + 1` 像素起算，再按偏移方向增减；模糊值为零时只计偏移。文本框先扣除这部分空间，再用于排版。工具以 DOM 实际断行和行框为基础，结合 Canvas 文字测量补充字形外伸，再加上效果预算生成 `effects_bounds`。这些值用于排版和溢出检查，像素边缘仍以实际 PNG 为准。

节点可以设置正整数 `max_lines`，超过行数或文本框边界时按 `overflow` 处理。`error` 报告节点及其文本框、内容和效果范围。`clip` 按节点框及行数限制裁切，并记录溢出。`shrink` 从角色字号逐个整数像素减小，按比例调整行高，直到排版满足约束或达到显式的 `min_font_size`。字号下限须为不大于角色字号的正整数，达到下限仍放不下时构建失败。`width: "content"` 不能与 `shrink` 同用。

渲染报告记录实际字号、行数、基线和边界。页面级 `checks.min_font_size` 可对低于阈值的实际字号发出警告，与节点自己的缩字下限独立。用 `project_preview_layout_variants` 比较不同画布尺寸、安全区和实际译文下的同一布局，检查长词、单位组合、换行和可读性。检查方式见[浏览器检查与显示场景](project-tools.md#浏览器检查与显示场景)。

### 4.3 修改影响与快照

`typography_usage` 和 `project_page_dependencies` 按角色列出引用它的布局和节点。构建状态的 `matches_typography` 由实际角色外观判断，包括解析后的字号、字体内容摘要、行高、字距和效果参数。字体路径不参与外观摘要，快照键由工程相对字体路径确定，完整字体文件按内容摘要跨页面共享，离线 HTML 内嵌实际文案的字体子集。修改说明、参考记录或未引用的角色时，无关页面的构建状态保持有效。可用 `project_rebuild_pages` 集中重建需要更新的页面。

字体文件变化但未正式更新摘要时，先处理资源校验错误。确认接受新文件后，通过更新规范登记新摘要，引用该字体的已有构建才按新依赖标记为过期。

构建快照使用自身保存的输入和字体查看。规范更新后按使用位置检查影响，显式重建受影响页面以更新当前快照。持久文件的历史由 Git 管理。

## 5. 已有工程采用文字规范

格式 4 项目使用仓库的 `scripts/adopt_typography.py` 显式采用当前格式。先审查每页内容并定义完整角色样式，准备符合[项目工具接口](project-tools.md)的文字规范 JSON，再准备一份按布局 ID、节点 ID 组织的映射，例如 `{"home":{"confirm-label":"button-primary"}}`。映射必须覆盖所有含文字的布局及其全部文字节点，纯图像布局无需填写。

先执行预检，检查返回的布局、待重建页面、备份目录和 `revision`。确认后使用同样的输入，追加 `--apply --expected-revision <预检返回的 revision>`。

```powershell
python scripts/adopt_typography.py --project-root <工程根目录> --typography <文字规范 JSON> --layout-styles <页面角色映射 JSON>
```

应用后，工程使用格式 5，文字节点引用已分配的角色。原项目索引、相关布局定义、构建记录以及含文字页面的原 HTML 和 PNG 归档到业务工程的本机目录 `.smartui/migrations/4-to-5/<revision>/`。历史备份留在原位置，由项目维护者按需移动。需要继续维护的文字页面使用当前布局显式构建，并在目标尺寸下复查。

## 6. 验证范围

在目标场景的真实背景和显示尺寸下复查实际 PNG。校准字体、字距、换行、描边、投影及显式溢出策略，核对角色层级和最终可读性。Unity、移动设备及动态场景中的运行态效果另行验收。

自动字体识别、富文本混排、运行时字号设置、多语言样式切换、多层文字效果、Unity 字体资产和材质生成属于独立能力。

平台指南补充：Microsoft 的 [Xbox Accessibility Guideline 101](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101) 区分平台、分辨率和文字大小设置，并说明从实际渲染图像测量文字的方式。它是游戏可访问性指南，不属于社区共识，也不能把其中的可见文字像素高度直接填作 SmartUI 的 `font_size`。

基于上述材料，文字设计采用以下判断：固定字号服务于内容层级和跨页一致性；字号、字重、描边、投影、背景及文本框共同校准；样片使用真实内容和明确的显示条件。未找到足以支持跨项目固定字号、固定描边比例或统一投影参数的证据，因此具体数值仍由项目参考和实测确定。多语言执行、玩家字号设置和运行态验证留在对应需求中实施，这些资料用于当前样片和页面的设计校准。
