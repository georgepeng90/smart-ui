# UI 设计稿和 Unity 交付检查

只检查本次变更的界面、控件和资源，以及受影响的引用。每项记为通过、失败、待验证或不适用，并关联截图、构建记录或 Unity 回执。

## 设计稿

- [ ] 已建立页面、功能区块、条目和内部元素的真实父子层级；无背景区块也有容器，内部元素未大量平铺第一层。
- [ ] 回复已同时嵌入干净稿和标注图并链接 inputs.json；标注包含不可见区块、刘海和手势区示意，示意不冒充真实设备。

- [ ] 已核对本次任务涉及的项目约定和公共资源。正式页面使用项目参考尺寸，例外注明原因。
- [ ] 图文组、可见边界、文字基线、独立角标和间距符合布局意图。长译文和大数值仍可阅读。
- [ ] 出设计稿或生成整页预览时，交付同一布局摘要的干净稿、人工评审标注图及 `inputs.json`。
- [ ] 按英文图例核对元素范围、贴边锚定、枢轴、拉伸方向和安全区。检查标记在查看尺寸下的清晰度及文案遮挡。
- [ ] 检查构建报告中未声明的约束。展示设备区域时保留完整设计区，核对外部尺寸用途与全屏背景延伸。
- [ ] 适用时核对代表状态及空、少量、满列表，确认遮罩、内容边距和末行留白。

- [ ] 重复条目的内部标记采用代表条目，密集标记可分散；覆盖所有不同状态，保留条目外框。
- [ ] 区块负责页面边缘适配，内部元素通常中心锚定；pivot 独立设置，按钮保持中心，例外有明确理由。

## Unity 交付

- [ ] 已读取实际 Prefab 层级核对区块和子元素归属，不能仅凭截图通过验收。

- [ ] 对本次页面执行构建预检和复验。记录参考尺寸结果、实际锚点、枢轴、引用和受管属性差异。
- [ ] 使用同一文案、状态、屏幕尺寸和安全区并排比较设计稿与 Unity 截图。参考尺寸使用 `project_compare_unity_screenshot`。
- [ ] 项目适配器将所用 Key 的权威源表、生成值及占位规则结果交给 `project_check_localization` 比对。
- [ ] 分别记录点击、滚动首尾、短内容拖动、回弹和实际业务行为的 Play Mode 证据。
- [ ] Unity 人工调整已执行差异检查。采纳项更新到所属设计记录和预览，相关依赖已复验。

## 同步 Unity 中采纳的修改

执行 `plan` 或 `verify`，在有受管属性差异时读取 `managed_differences`。逐项比较上次基线、当前 Unity 值和当前设计值。结构或对象身份不一致时，先处理结构迁移。

将确认采纳的调整写入正式布局、控件定义或图素源记录。涉及图素时先确认可维护来源，再更新导出和依赖。重建受影响预览。为已经与 Unity 实际 Prefab 一致的设计准备 `apply` 请求，设置 `adopt_matching=true`。工具在对象身份及所有受管属性均符合设计时更新基线，保留 Prefab 文件。否则报告冲突，供继续审阅。

再次执行普通复验，确认已采纳值仍保持，并记录需要 Play Mode 或目标设备验证的事项。
