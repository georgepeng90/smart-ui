# Unity 基础预制体和页面嵌套复用实施方案

第二阶段以“一个基础控件、一个变体、两个页面”验证预制体复用：共用外观在基础预制体上修改，页面保留独立文案和引用，两个页面预制体文件不因继承变化而重写。

当前实现基线为 SmartUI PhotoCraft v0.14.1，接口见 [Unity 接入工具](unity-tools.md)。已提供控件制作定义、浏览器控件节点、Unity CLI 调度和通用 Editor 构建包。本文说明实现边界及尚待实际工程执行的验收。验证工程待选；工程数据留在业务工程，工具代码与通用说明留在本仓库。Python 回归和 C# 编译检查不代表 Unity 导入、保存重开或运行验收通过。

## 1 本阶段的范围

本阶段实现固定设计尺寸下的基础控件构建、变体创建、页面嵌套、静态 Sprite 和 TextMeshPro 映射，以及保留对象身份的有限更新。实际保存后的引用保持待工程验收。首个控件采用由背景 Image、标题 TextMeshProUGUI 和 Button 组成的按钮；共用状态图显式绑定到标准 Button 支持的状态。项目自研控件通过后续适配扩展。

浏览器页面与 Unity 页面共用一份页面定义。浏览器负责预览和静态布局计算，Unity 页面保留控件引用及排列结构。运行时内容测量、自动重排、安全区变化、完整字体效果映射属于第三阶段；业务生命周期、本地化系统、动画、滚动与正式回调接入属于第四阶段。固定样例的显示、简单点击和外部序列化引用仍在本阶段验证。

当前可新建预制体，修改已声明的属性，增减实例参数或调整页面排列。已生成资源的节点增删、父级变化、组件类型、嵌套来源、Button 目标或公开槽位变更需要单独迁移。

## 2 构建输入和产物登记

### 三类控件分别处理

| 类型 | 制作输入 | Unity 产物及更新责任 |
| --- | --- | --- |
| 生成型基础控件 | 内部结构、默认值、资源与文字角色、公开槽位和允许的实例参数 | 创建普通 Prefab；工具仅维护声明的对象和属性 |
| 生成型变体 | 基础控件 ID 和本地差异 | 创建真正的 Prefab Variant；只保存自身差异，保持基础连接 |
| 登记复用的已有控件 | 实际 Prefab、槽位对象映射、使用约定；浏览器使用所需的明确预览定义 | 保持原有制作归属；登记不授予工具重建或修改内部结构的权限 |

公开目录保存用途、来源 ID、尺寸范围、槽位类型和状态图；制作定义保存在 `construction.json.recipes`，不能仅根据目录推断按钮内部结构。当前字段和示例见接口文档。

| 输入 | 内容与限制 |
| --- | --- |
| 内部节点树 | 稳定节点 ID、父子顺序、设计尺寸与矩形；首轮使用分组、图像、文字和嵌套控件节点 |
| 组件角色和初始值 | 节点类型决定当前支持的标准组件；图像和文字节点保存资产、文案及文字角色；可选 Button 位于控件根节点 |
| 槽位目标 | `slot_id` 指向 `node_id` 和 `rect/image/text/button` 组件；当前只公开本控件节点，不能跨内部嵌套实例公开槽位 |
| 参数目标 | 沿用公开参数的类型和必需条件，补足它对应的具体组件属性；项目适配器校验属性是否受支持 |
| 变体差异 | 以基础控件的稳定节点或槽位为目标，明确要覆盖的属性和值；不保存一份展开后的内部树 |
| 控件依赖 | 生成型基础控件的内部嵌套节点与目录中的依赖核对。生成型变体继承基础控件的嵌套依赖，目录中的 `dependencies` 填空数组 |

内部默认值属于基础控件，页面参数属于具体实例。省略参数表示继承；显式提供与基础值相同的参数仍表达固定该值的意图，不能因值相同而改写为继承。变体的本地差异、继承解析后的预览数据及实际 Unity 覆盖分别保留，不能用第一阶段清单里的展开定义代替变体差异。

### 构建并登记控件后再准备页面请求

控件与页面使用各自的构建请求。准备页面前，页面引用的控件须已经登记并通过当前文件核对。手工静态实例清单由 `project_prepare_unity_handoff` 单独准备。

1. 定义控件制作输入，允许生成型控件尚无产物。
2. 准备控件构建计划，明确新建或更新、输入摘要、适配器版本、输出路径和已有产物的预期身份。
3. SmartUI 通过 Unity CLI 调用目标工程内的固定 C# Editor 构建入口，按依赖先创建基础控件，再创建变体或复合控件；由 Unity 实际保存、重新加载并核对对象和源连接。
4. 返回实际 GUID、路径、槽位对象、输入摘要和核对结果。Python 工具核对当前来源与登记 revision，再更新产物登记和使用文档。
5. 全部引用控件就绪后，从正式页面定义生成页面构建请求，再通过同一 CLI 执行链路创建页面排列容器和嵌套实例，保存并核验页面预制体。

控件更新可能使派生控件的登记过期。应复验并更新受影响的登记；如果变体自身没有差异变化，则不保存变体文件。登记记录更新与 Unity 预制体写入是两项不同操作。

制作输入使用独立的 `construction.json` 格式 1；公开目录及已有文件交付协议仍各自使用格式 1。正式页面在现有节点联合类型中加入 `control`，不复制一份布局。内部树、默认值和页面引用须明确填写，不能从 PNG、文字说明或已有 Prefab 猜测。

## 3 页面定义和文档保持一致

页面新增 `control` 节点，保存稳定实例 ID、`control_id`、现有布局字段及显式设计参数。它是页面树中的叶节点，内部结构由控件定义提供。`group.component_id` 仍表示 PhotoCraft 组件使用约定，不能兼作 Unity 控件身份。

浏览器构建时临时展开控件，派生节点使用页面实例 ID 和控件内部节点 ID 组成的命名空间。展开结果可以作为当前预览的构建证据保存，但不可编辑，也不能作为 Unity 创建控件内部对象的输入。预览当前性检查同时比较页面定义、所用控件与变体差异、实际图像和文字角色，不能只看页面本身的摘要。

业务绑定按 `page_id + instance_id + slot_id` 保存到 `construction.json.bindings`。浏览器预览不要求填写业务键；准备 Unity 页面时核对实例、公开业务槽位和必需绑定，绑定键随执行记录保存供后续项目适配器使用。当前不生成事件回调代码。页面请求从同一读取快照解析页面、控件、资源和绑定，不再要求重复手填坐标。

Unity 页面输入保留有序分组、普通图文及控件引用。首轮支持能力必须列入适配器说明；不支持的布局或字体效果明确报错，不能先展开成图片而假称已经接入。固定尺寸样例可以使用浏览器解析出的静态矩形，但不得将其表述为运行时约束布局。

控件使用文档由登记资料生成。登记上下文的 `uses` 来自已登记依赖和清单请求。正式页面中的直接实例位置通过 `project_page_dependencies` 查询。

## 4 Unity 侧的创建和更新

### 通过 CLI 在 Editor 中实际构建

基础控件、变体和页面的生成都经过同一条执行链路：

```text
SmartUI 制作定义和构建计划
  → Unity CLI 指定当前工程
  → 工程内固定的 C# Editor 构建入口
  → Unity 创建 GameObject、组件、层级及资源引用
  → Unity 保存 Prefab，重新加载并核验
  → 返回真实资产身份与结果，更新控件登记和使用文档
```

Python 工具负责生成和校验制作输入、调度 CLI、检查执行结果及维护项目资料。Editor 构建器负责创建 RectTransform、Image、TextMeshProUGUI、Button 等对象和组件，导入 Sprite、绑定字体，以及创建基础 Prefab、变体和嵌套页面。预制体序列化和对象 fileID 由 Unity 生成，登记依据实际保存结果。

Editor 包通过 Unity Pipeline 注册 `smartui execute` 命令和必填 `request_path` 参数。Python 客户端先通过 CLI 查询实际命令目录，再使用明确的工程路径调用。请求的 `operation` 为 `plan/apply/verify`，分别执行预检、应用或只读复验。超时后查询同一次请求的结果，不能重复创建。CLI 参数和回执处理有进程替身测试；选定工程前尚未实际调用这一注册命令。

### 最小 Editor 包

通用包位于 `unity/com.smartui.ugui/`，使用 Editor 专用程序集。Pipeline 命令桥与核心构建器分开，注册接口对应 `com.unity.pipeline@0.10.0-exp.1`。字体与材质由项目显式映射；宿主挂载和业务引用由后续项目适配器处理。本阶段不增加每帧扫描的运行时绑定组件，Player 不读取编辑器对象映射或使用 `UnityEditor` API。

包通过项目能够复现的依赖方式引入；初期可使用业务工程内的嵌入包或明确的 Git 包引用，不把开发者机器上的绝对路径写成工程依赖。选定验证工程后，先核对或引入版本明确的 Unity Pipeline 和 SmartUI Editor 包，等待依赖解析和脚本编译完成，再确认 CLI 能发现构建入口。Pipeline 可用 `unity pipeline install` 指定工程路径和包版本；已有可用安装不强制升级。SmartUI 包按工程依赖管理方式引入，其命令注册适配已核对的 Pipeline 接口。首次包接入与控件构建分开，避免调用尚未注册的命令；核心构建逻辑保存在版本化 C# 包中。

### 基础控件、变体和页面的保存方式

| 目标 | 创建方式 | 后续更新 |
| --- | --- | --- |
| 基础控件 | 从制作输入创建普通根对象和受支持的组件，保存成基础 Prefab | 沿用原路径和 `.meta`，复用已加载对象，只修改自身受管属性；保存重开后核对对象身份和引用 |
| 变体 | `PrefabUtility.InstantiatePrefab` 实例化基础控件，设置声明差异，再把实例最外层根保存为新资源 | 保留基础连接，只调整本地覆盖；继承值变化不转成覆盖 |
| 页面 | 创建页面自有根和布局容器，在容器下通过 `InstantiatePrefab` 放入基础或变体，再保存页面根 | 修改已有节点的排列和显式参数，保持嵌套连接 |

Unity 保存普通根时会保留其子预制体实例的嵌套关系；保存预制体实例的最外层根会生成变体。这是上述创建路径的依据。[Unity 保存规则](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/saveasprefabasset)

页面采用以下结构，示例名称仅用于说明，身份由稳定 ID 管理。

```text
PageRoot
  PrimaryActionLayout              页面自己的排列容器
    PrimaryButton                  基础预制体实例
  SecondaryActionLayout            另一个独立实例的排列容器
    PrimaryButton                  同一基础预制体的另一实例
```

容器负责页面上的位置和大小；实例根与容器的填充关系是明确的页面归属。控件维护内部图像、文字与共用状态。Unity 对实例根 RectTransform 的尺寸、锚点和 pivot 有默认覆盖规则，因此基础根尺寸变更不承诺自动改变所有版式。[Unity 实例覆盖规则](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-gameobjects/prefabs/override/prefab-instance-overrides)

现有 Prefab 采用 `LoadPrefabContents` 加载，确认有可写变化后才保存回同一路径，最后在 `finally` 中 `UnloadPrefabContents`。只读复验不调用保存；不能用退出时自动保存的 `EditPrefabContentsScope` 包装只读检查或失败放弃路径。[加载规则](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/loadprefabcontents)、[自动保存作用域](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/editprefabcontentsscope)

属性修改优先使用 `SerializedObject` 和 `SerializedProperty`；通过组件 setter 修改实例时，要正确记录预制体修改。删除某个先前由工具写入的实例参数时，只恢复该属性在当前继承层的继承状态。不能调用 Apply All 把页面差异写进基础控件，也不能用 Revert All 清除项目差异。[修改记录](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/recordprefabinstancepropertymodifications)、[单属性恢复](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/revertpropertyoverride)

### 对象身份和槽位定位

设计对象采用稳定的控件、节点和组件角色 ID。实际资产对象采用 GUID 与有符号 64 位 local fileID；页面实例还必须带本页实例范围。不得把 `GetInstanceID`、显示名称或层级序号当成持久身份。

解析页面槽位时先用页面实例 ID 定位它自己的布局容器，核对其中唯一的直接嵌套实例及所选预制体 GUID，再在该实例范围内按槽位来源控件和 fileID 查找组件。继承槽位使用指定来源资产层级，不一律追到最原始基础资源。复合控件内部重复嵌套同一控件时，还需沿定义中的内部实例 ID 缩小范围；映射不足或结果不唯一就报错。[指定来源资产查找](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/getcorrespondingobjectfromsourceatpath)

对象映射在资源保存并重新加载后记录，不保存临时预览场景的对象 ID。嵌套槽位回执包含本页自有容器的 `scope_file_id`，以及来源控件的 `control_id/guid/file_id`。Editor 在该实例范围内核对实际对象；Python 核对容器对象及来源登记。不能要求所有嵌套组件都在页面 YAML 中有独立对象声明，Unity 只在需要本地引用时生成对应的 stripped 占位记录。[嵌套预制体序列化](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-scenes/text-scene-format/yaml-prefab-serialization)

Unity 覆写 Prefab 时会尝试按名称维持引用，同名对象及同一对象上的重复组件类型存在歧义。稳定设计 ID 本身不能消除保存 API 的歧义；“同一基础控件在页面里出现两次”必须作为保存策略的必过用例，失败时先修正保存方式，不能改掉用例或重建对象掩盖问题。[Prefab 保存的引用限制](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityeditor/prefabutility/saveasprefabasset)

## 5 更新判断和持久记录

每个资源分别保存工具上次成功写入的声明、实际对象映射和核验结果。基础控件比较自身属性，变体比较本地差异，页面比较本地排列和显式参数。比较时区分“未覆盖”和“显式覆盖为某值”，不把已经变化的继承值当作人工冲突。

| 变化 | 写入范围 | 复验范围 |
| --- | --- | --- |
| 基础控件的未覆盖外观改变 | 基础控件及必要的共享资源 | 所有依赖变体和页面；它们没有本地变化时不保存 |
| 变体的本地差异改变 | 对应变体 | 使用该变体的页面 |
| 页面文案、位置或显式绑定改变 | 对应页面或其接入记录 | 对应实例和引用 |
| 输入及目标声明均未变化 | 不写入 | 必要的只读一致性检查 |
| 槽位身份、连接或人工受管属性出现冲突 | 不进入该单元写入 | 返回具体对象、属性和预期值，修正后重新预检 |

页面直接输入摘要不包含控件文件摘要、被继承的最终值或全局 revision。控件和资源变化进入依赖摘要，触发复验。依赖摘要变化只是检查依据，不能直接解释为页面必须重写。目标文件字节、受管属性和本地覆盖仍要重新读取，避免只比较 SmartUI 输入而漏掉工程内改动。

计划明确“新建、写入、仅复验、保持、冲突”。应用前复查来源、适配器配置、目标摘要和本次相关的未保存 Editor 修改，变化后要求重做预检。相关资源未保存时指出具体目标，不替用户保存或丢弃其他工作。

持久资料按下列归属维护。

| 位置 | 维护者与内容 |
| --- | --- |
| `smart-ui/unity/registry.json` | 项目工具维护公开目录和经文件核对的产物索引 |
| `smart-ui/unity/construction.json` | 项目工具维护制作定义、输出目录、TMP 字体和材质映射，以及当前页面业务键 |
| `smart-ui/unity/operations/<request_id>/` | 固定输入请求、执行状态和实际结果；超时后核对同一次操作 |
| `smart-ui/unity/import-state/` | Editor 写入每个目标的当前成功基线、对象映射和必要的未完成写入状态 |
| `smart-ui/docs/unity-controls.md` | 项目工具生成当前使用说明和产物状态 |
| `Assets/<工程约定目录>/` | 实际 Sprite、基础 Prefab、Variant 和页面 Prefab |
| `.smartui/` | 可再生成的缓存、详细诊断和锁；清理后不得丢失判断已落盘资源所需的状态 |

请求记录预期输入，结果记录目标状态、请求摘要和可核对的资产身份。资源保存后重新加载并通过核对，才推进该资源的成功基线。资源写入或验证中断时保留 `.pending`，登记未完成时保留请求状态。同一次执行留下完整结果后，可用 `project_reconcile_unity_build` 继续核对。始终没有完整结果或仍有未完成写入记录时，人工检查目标 Prefab、`.meta` 和基线。当前工具阻止新构建或冲突目标再次写入，尚无自动补回执、回滚或解锁操作。相同输入准备新请求并复验时，登记和成功基线也不因时间戳产生变化。

## 6 验证工程的条件

首轮选择用户当前正在使用的 Unity 6 uGUI 工程和实际补丁版本，不为验证擅自升级 Unity、切换分支或建立副本。工程整体不必没有其他改动，但本次输出、引用资源和测试入口的当前状态须可核对。

| 条件 | 在首次写入前需要确认的内容 |
| --- | --- |
| 工程和 Editor | 当前目录、当前分支、实际 Unity 版本；脚本可编译，所需场景或局部 UI 测试入口可运行 |
| 调用入口 | Unity CLI 能明确定位该工程和已有 Editor；Pipeline 和 SmartUI Editor 包完成依赖解析及编译，CLI 能发现并调用真实的构建、复验与测试入口 |
| UI 依赖 | 已安装的 uGUI、TMP 和测试包版本明确；包的程序集引用可以编译 |
| 资源序列化 | 目标 Prefab 使用当前文本格式，`.meta` 随 Git 保存；路径、GUID 和对象 fileID 可核对，无 Missing Script |
| 可写范围 | 基础、变体、页面、测试夹具和 SmartUI 资料各有明确目录；不覆盖来源不明的同名文件 |
| 图像与字体 | 至少一套合法背景图及状态图，一份可用于实际样本文案的 TMP Font Asset 和材质；源图几何、字体字形和角色映射齐全 |
| 页面宿主 | Canvas、CanvasScaler、挂载位置、设计尺寸、渲染模式和输入方式明确；复用现有宿主，或显式建立工程内测试场景 |
| 引用样例 | 在已保存测试场景中实例化页面，由独立验证对象的序列化字段分别引用重复控件的具体组件；重开场景后可核对各自身份 |
| 验证入口 | 可执行 Edit Mode 检查和最小 Play Mode 显示、点击验证，能取得对应 Canvas 模式的实际显示结果 |

优先选择依赖简单、局部 UI 不必等待线上登录的工程；已有代表按钮、TMP 资源和局部测试场景会减少适配工作。这些是选择时的便利条件，不要求工程已经有完整控件工厂或成熟 UI 自动化。

首轮不要求正式 Addressables/AssetBundle 发布、联网业务、完整本地化、复杂动画或移动设备验收。编辑器阶段选定一个明确的设计尺寸；动态宽高比和安全区场景由第三阶段扩大。工程缺少必要字体、资源或运行入口时先补齐或选择其他验证工程，不用替代资源掩盖问题。

入口探查先读取 `unity --help`、`unity command --help`，然后用 `unity list --project-path <工程绝对路径>` 查询工程实际能力。已有 Editor 时优先调用其注册命令；不能直接假定 `unity test` 会复用已有进程，也不能为测试再启动第二个 Editor 打开同一工程。若 CLI 的现有能力无法完成某项操作，明确说明缺口并使用同一工程内适用的 Editor 入口。未选工程前不连接或修改任一业务工程。

## 7 样例和验收方法

贯穿样例采用 `button.primary` 基础控件和一个只改变背景的变体。页面 A 放两个基础控件实例，分别显示“开始”和“返回”；页面 B 使用变体并保留自己的文案。在测试场景中实例化两个页面，由同一场景中的独立验证对象分别序列化引用 A 页两个控件及 B 页变体内的目标组件。保存并重开场景后核对指向具体实例，而不仅检查字段非空。Prefab 自身不保存对场景对象的反向引用；控件内部和页面内部的组件引用另在保存重开检查中核对。

先修改基础控件中未被覆盖的标题颜色。预期两个页面的标题外观更新，实例文案、变体背景和外部引用保持，两个页面 Prefab 与 `.meta` 的字节均不变。修改颜色是为了避免把变体有意覆盖的背景误判为未传播。

| 用例 | 必须证明的行为 |
| --- | --- |
| 首次构建 | 从尚无生成产物开始，通过 CLI 创建基础控件、变体和嵌套页面；回传身份与实际文件一致，保存重开后槽位和组件类型正确 |
| 重复实例 | 页面 A 的两个同源实例能独立定位和改文案；已保存测试场景中的验证字段经更新、重开后仍分别指向原来的具体实例 |
| 共用外观变化 | 上述标题颜色沿继承生效；两个页面及无本地变化的变体不被保存 |
| 变体本地修改 | 只修改变体背景，基础控件和其他页面实例不受影响；引用该变体的页面只读复验 |
| 显式参数和恢复继承 | 基础值为 A、变体本地值为 V、页面覆盖为 P；移除页面参数后得到 V，变体本地覆盖仍在 |
| 显式等值参数 | 页面显式值等于当前继承值，保存重开后仍保持固定值意图；上游值变化不能让其意外跟随 |
| 无改动重导 | Prefab、`.meta`、当前登记和成功基线字节均不变；复验代码不额外保存资源 |
| 只改一个页面 | 改页面 A 的排列或文案，只写该页；页面 B、基础控件和变体字节不变 |
| 错误和冲突 | 缺资源、过期输入、槽位失效、歧义身份、目标未保存修改或人工受管属性偏离时，指出具体对象并在写入前拒绝 |
| 中断和验证失败 | 准确列出已落盘、未执行及未验证单元；成功基线不冒进，再次执行前重新读取实际状态 |

显式等值覆盖能否在所选 Unity 版本稳定保存，需在首个 API 样例中实测。如果 Unity 会将其归一为继承，应明确返回该语义尚不支持，先解决表示方式；不能悄悄接受并改变参数含义。同名嵌套对象的保存引用、变体恢复继承的层级，以及持久对象映射到加载场景的转换也在这一样例中验证。

结构验收记录具体 GUID、fileID、源连接和覆盖归属；显示验收记录实际场景与 Canvas 参数及截图；点击验收只覆盖样例路径。浏览器截图不替代 Unity 显示验证，编辑器通过不代表设备或用户美术验收。

## 8 实施顺序和完成门槛

| 步骤 | 交付 | 进入下一步的条件 |
| --- | --- | --- |
| 1 通用制作输入与页面预览 | 已实现控件树、变体差异、槽位目标、业务键、`control` 节点、派生预览及控件依赖 | Python 回归验证引用、过期状态及同一正式页面驱动导出 |
| 2 通用 CLI 与 Editor 构建实现 | 已提供 CLI 命令发现和执行、真实结果登记、Sprite/TMP 映射、基础与变体构建、页面嵌套及有限更新 | Python 与离线编译只覆盖工具层；实际资源保存语义仍待验证 |
| 3 工程接入 | 待选工程并引入 Editor 包，确认字体、命令发现及测试入口 | 实际 CLI 调用和对象保存重开通过 |
| 4 复用验收 | 待执行本节样例矩阵，核对场景中的具体对象引用 | 共用外观生效且两个页面不重写；等值覆盖、恢复继承、中断处理及引用保持均有实际结果 |

工程选择前先交付通用实现；真实工程验证是独立的后续工作。验证结果可能要求调整保存或对象映射实现。第二阶段的工程验收以复用样例通过为结束条件，不能以导出文件、模拟执行或 C# 编译通过代替。
