# 在 Krita 中绘制与修改源文件

使用 `krita_status`、`krita_list_brushes`、`krita_inspect_document`、`krita_execute_batch` 和 `krita_preview` 操作运行中的 Krita。具体操作参数见 [接口约定](../../docs/bridge-contract.md)。本工具执行明确的笔触和结构化操作；不要承诺自动获得某种艺术质量或精确复现复杂画风。

## 先确认当前状态

- 调用状态工具验证扩展实际响应；仅看到启动信息文件不代表连接可用。
- 编辑现有作品时，先根据状态中的文档路径确认用户指定的绝对 `.kra` 是否已打开；已打开则直接检查文档与递归图层树，未打开才执行 `document.open`。重复打开会报错。使用节点 UUID；只有名称唯一时才使用 `name:名称`。
- 查询已安装笔刷预设，使用返回的精确名称。预设缺失时报告名称和问题，不换用近似预设。
- 开始局部修改前，确认目标图层、蒙版和需要保留的部分；利用检查结果中的像素哈希记录未修改图层。

## 批量执行明确的绘制操作

按视觉目的安排分组、绘画图层和透明度蒙版，将同一阶段的多个操作合并为一次批量调用。描边使用 Krita 原生笔刷；几何填色和蒙版选区应如实说明。

`line` 使用整数像素坐标，可分别指定首尾压力。`path` 支持直线、二次与三次贝塞尔曲线，但 Krita 5.3 当前 Python 接口没有连续自由手绘的 `StrokePoint` API，不要承诺逐点压力、倾角和时间信息完整保留。当前蒙版操作只覆盖原生透明度蒙版。

先完成可检查的构图或组件，再导出预览判断结果，依据预览继续修改。不要因工具返回成功就断言视觉效果符合要求。

批量调用不是事务：遇错停止，已经完成的操作保留，失败项自身也可能部分生效。`completed` 只列出完整返回的操作；未列入其中不代表未修改。根据错误中的请求 ID、结果路径以及实际文档和图层检查结果，确定已经生效的内容，再决定如何继续。超时后不要自动重发修改请求，以免重复绘制；查看对应响应文件或重新检查文档。

## 保存、预览和局部修改

保存为用户指定的 `.kra` 源文件，并导出 PNG 预览；交付时同时提供源文件与预览路径。已有文档继续使用原路径，只有用户需要副本时才另存。

局部修改继续使用同一个源文件；已打开时直接重新检查节点，关闭后才重新打开。针对指定图层或蒙版操作。清空图层是明确的破坏性操作，只在用户要求替换该层内容时使用。修改后比较未涉及绘画图层的像素哈希，保存并再次检查预览。关闭文档前先保存。
