# 使用已有资产组合页面

页面组合管理实例、位置、尺寸、层级和文字，组件制作管理可复用外观。先读 `project_context`，查询已有组件运行、图像版本和组合，再决定缺少什么。已有资产能够满足任务时直接引用，不因需要完整页面而启动整页基础 UI 绘制，也不用共享绘制函数重新生成已有组件。

调用前阅读[独立图像资产与静态组合预览](../../docs/project-tools.md#独立图像资产与静态组合预览)。当前工具生成 PNG 组合快照，尚无可更新布局对象、浏览器预览器、九宫格或自动换行。后续浏览器方案见[总体规划](../../docs/toolchain-roadmap.md#46-页面布局与浏览器预览方向)，不能把规划中的接口当作现有工具调用。

## 选择修改入口

| 任务 | 处理方式 |
| --- | --- |
| 移动按钮、调整间距、修改文案或层级 | 保留资产版本，修改组合节点并创建新快照 |
| 修改材质、轮廓或某个组件状态 | 用 [krita-drawing](../krita-drawing/SKILL.md) 修改对应源组件，再组合检查受影响实例 |
| 生成或编辑独立图标 | 用 [icon-assets](../icon-assets/SKILL.md) 制作和登记图像，组合时引用明确版本 |
| 判断目标风格或定位视觉偏差 | 用 [reference-style](../reference-style/SKILL.md) 查看依据，区分资产外观、导出、布局、文字和运行时问题 |

尺寸变化先检查项目声明的伸缩方式和最小尺寸。当前组合只支持等比缩放，不能将其冒充九宫格；需要不同形状时才制作新变体。已有合适资源但所需伸缩能力未实现时，说明具体缺口，不通过整页重绘、静默拉伸或压平可编辑内容掩盖问题。

## 引用与检查

1. 确定参考分辨率、目标背景、实例位置和文字。同一资产的多个实例使用不同节点 ID，复用同一来源版本。将布局主体与图像透明边距区分；当前接口的目标矩形作用于完整图像或显式裁切区域，不自动理解项目的内容区域。
2. 已登记图像通过 `project_get_image` 校验和查看；使用项目选用版本时，先从上下文解析出确切版本。已有未登记 PNG 用 `project_register_image` 的 `imported` 来源登记真实说明，组合直接引用确切的登记版本。只有任务要求改变项目选用版本时才调用 `project_select_image`，不因一次组合顺带改变其他页面应采用的版本。组件预览引用实际成功 `component_id/run_id`，不要把检查预览宣称为已完成正式切图。
3. 新页面可以使用任务明确允许的业务占位，但应在项目资料中记录占位范围、用途和替换需求，汇报时明确指出。已声明的正式资产缺失或摘要不符必须报错，不能自动换成占位。
4. 用 `project_create_composition` 引用实际来源，保持文字为独立节点。遵守当前节点数量、字体、单行文字和画布边界要求；不能为了满足上限把所有文字压成一张位图。超出能力时指出受影响的节点和需求。
5. 查看实际组合，检查目标尺寸下的留白、文字关系、状态辨识和整体层次。布局反馈只修改组合节点；资产反馈修改对应来源后显式创建新组合，不改写旧快照，也不宣称已自动找出和更新全部引用。

展示最新组合 ID、预览路径、实际资产版本和未完成项。历史结果用 `project_get_composition` 读取。选用版本、技术校验、模型视觉结论和用户确认分别表达；流程不增加逐步骤用户审批。
